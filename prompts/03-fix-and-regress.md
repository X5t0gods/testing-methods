# 修复与回归提示词

```text
任务：在授权范围内修复已确认的 {{缺陷}}，并提供回归证据。

允许修改：{{生产文件与对应测试文件}}
业务预期：{{规则}}
禁止触碰：{{边界}}
验证命令、数据隔离与清理方式：{{前置}}

流程：
1. 先加入最小复现用例，确认它因目标缺陷而失败，保存真实输出。
2. 做可审查的最小修复，不混入无关重构、格式化或依赖升级。
3. 运行原用例与必要相邻边界，再运行模块子集。
4. 按影响范围做集成/全量回归，记录当前源码快照。
5. 审查 diff、核心断言、数据库副作用和清理结果。

纪律：
- 不通过放宽断言、降低业务阈值或缩小数据规模伪造通过。
- 若原测试预期错误，先说明业务依据和原断言问题，再独立审查修正。
- 若出现新失败，保留现场并定位具体变更；保护其他人的未提交工作。
- 未执行、超时、缺环境和跳过分别报告。

输出：现象、业务依据、根因、修复摘要、失败→通过证据、回归范围、遗留。
```
