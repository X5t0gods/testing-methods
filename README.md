## 我如何开展测试

1. **建立基线**：记录源码状态、依赖环境、测试数量、覆盖率和已知失败，区分单测与集成测试。
2. **按业务风险安排顺序**：先验证金额、库存、权限和事务一致性，再处理报表、分析与一般页面行为。
3. **限定单轮范围**：明确模块、文件和验收条件，使用边界值、状态迁移、等价类与数据不变量设计用例。
4. **用失败复现确认缺陷**：先证明当前实现违反明确的业务预期，再修改生产代码，不通过放宽断言掩盖问题。
5. **分层回归并记录证据**：先跑缺陷用例，再跑相关测试子集，最后在源码状态稳定后执行收尾回归。
6. **如实交付**：每项结论绑定命令、运行范围、实际输出和限制；未运行、跳过、失败分别记录。

## 快速体验

独立示例使用 Python 3.11+ 标准库，不需要安装依赖：

```powershell
# 金额边界：旧实现预期失败，退出码为 1
python examples/money_regression.py --mode before

# 修复实现预期全部通过，退出码为 0
python examples/money_regression.py --mode after

# 多门店同日汇总：分别观察覆盖与累加的差异
python examples/report_aggregation.py --mode before
python examples/report_aggregation.py --mode after

# 验证本仓库的文档链接、证据摘要与版本信息
python tools/verify_docs.py
```

示例是为了展示测试推理而重新编写的教学代码，**不等于原项目源码或原项目性能基准**。

## 技术与职责说明

案例系统涉及 FastAPI、SQLAlchemy、MySQL、pytest、coverage.py、Vue、TypeScript 与浏览器运行时检查。测试工作使用 AI 辅助代码检索、候选用例生成与修复建议；测试范围、业务口径、证据审查与验收标准需要人工判断。该作品集展示测试设计与工程实践，不把 AI 生成过程表述为全部手工独立完成。
