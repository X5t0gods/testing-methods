## 2. 历史交付基线

另一份较早的阶段交付材料记录全量 **599 passed**，无集成测试子集 **248 passed、351 deselected**。这与专项的 772 passed 属于不同快照与运行范围，**不能直接相减声称“新增 173 条独立测试”**，也不能据此推算缺陷发现率。

历史全应用覆盖率约 83% 的记录同样不能与两个报表文件的 100% 覆盖直接比较。若需要前后严谨比较，应在相同源码边界、配置和数据条件下重跑并保存两份报告。

## 3. 历史性能与并发记录

数据来自项目既有性能报告。报告描述的环境为 Windows、Python、MySQL、单个应用进程，模拟数据约 **50,000 笔交易、3,005 个 SKU**。延迟判定基准使用 5 个压测客户端；并发正确性另用 10 个客户端。客户端并发数不等于服务器进程数。

| 测试对象 | 历史结果 | 条件与限制 |
| --- | --- | --- |
| 结算接口 | P95 152.4 ms；150 样本、0 失败 | 本地模拟负载，不能外推为生产 SLA |
| 条码解析 | P95 62.7 ms；300 样本、0 失败 | 使用命中条码，不能代表所有输入分布 |
| 库存普通分页 | P95 63.9 ms；100 样本、0 失败 | 普通查询路径 |
| 库存状态筛选 | P95 1035.2 ms，超过目标 800 ms | 记录为未达标，不能用普通分页结果代替 |
| 并发结算正确性 | 10 客户端 × 10 单；100/100 成功，库存勾稽不符 0 行 | 原报告记录了单号、请求标识、记录增量与库存验证；不等于高压容量结论 |

历史定位指出，库存状态筛选需要拉取候选数据后计算状态再过滤，与普通 SQL 分页路径不同。这个结果说明测试需要覆盖不同执行路径；本仓库没有宣称该历史性能问题已经优化。

## 4. 不纳入效果宣传的内容

- 不把“所有用例通过”解释为“系统零缺陷”。
- 不把跳过的数据库测试、Mock 页面和未运行的步骤写成已验证。
- 不把本机启动等价验证写成容器编排验证；既有记录说明本机未完成 Docker 运行验证。
- 不把算法内部计时当成 HTTP 端到端耗时，也不把机器总内存当成算法内存占用。
- 不公布无法以同口径记录支持的提效百分比、成本节约、缺陷总数或个人工作量。

本库公开方法、模块清单、独立示例和经过筛选的证据摘要。原始项目源码、数据、账号、日志与聊天记录均不公开。

来源 SHA-256 用于材料持有者核对摘录对应的原始文件，**不等于第三方审计或结果真实性证明**。原始材料与完整实验环境不可见时，外部读者无法独立复现全部项目指标。可运行示例只用于检验测试方法本身，不补足这项证据限制。
