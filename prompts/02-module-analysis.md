# 模块定位与用例设计提示词

```text
任务：分析 {{模块}} 的 {{业务风险}}，形成能够验证的用例方案。

允许读取：{{文件清单}}
已确认业务规则：{{依据}}
已知基线与限制：{{记录}}
本阶段是否允许修改代码：{{授权}}

按顺序完成：
1. 清点相关入口、权限、状态和依赖，只查本轮相关路径。
2. 对照业务规则，检查边界、异常路径、幂等、事务与数据不变量。
3. 区分候选风险和已确认缺陷；给触发条件、证据位置和反例。
4. 用等价类、边界值、状态迁移或决策表设计最小用例。
5. 说明每条用例为什么能识别目标问题，以及需要检查的数据库副作用。

输出：
场景 | 业务依据 | 输入/前置 | 预期 | 观察点 | 验证方式 | 风险

业务口径冲突时列出具体分歧，不凭当前实现自行决定正确口径。
```
